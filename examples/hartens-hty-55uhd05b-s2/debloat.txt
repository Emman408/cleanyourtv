# Hartens HTY-55UHD05B-S2 55" 4K (CVTE chassis CV9632-K55, MediaTek MT9632, panel LC550EQC-SPA2), YaOS
# (Yandex TV OS) on Android 9 (API 28), build PPR2.180905.006.A1, CVTE software CV9632-K55-V1.00.11, Russia.
# About 1.3 GB of RAM, 1920x1080 UI at density 320, no Google Play or Play services on this OS.
# Stock launcher: com.yandex.tv.home (kept enabled, see below). HDMI, AV and the tuner play in com.yandex.tv.live.
#
# Apply:   TV_HOST=<tv ip> tools/disable.sh examples/hartens-hty-55uhd05b-s2/debloat.txt
# Undo:    TV_HOST=<tv ip> tools/restore.sh examples/hartens-hty-55uhd05b-s2/debloat.txt com.yandex.tv.home
# Launcher: TV_HOST=<tv ip> STOCK_LAUNCHER=none launcher/build-and-install.sh, then
#           TV_HOST=<tv ip> tools/theme.sh examples/hartens-hty-55uhd05b-s2 (config.json: dock, input_uri_scheme)
# Everything is DISABLED, not uninstalled; comment out any line you want to keep. Nothing came back after a reboot.
#
# Getting ADB: Developer options has no USB debugging toggle on this firmware. It is "ADB Mode" in the CVTE
# service menu: on the Yandex home screen hold Menu (three bars) for about a second, then press Left, Up,
# Left, Up and Back. The menu shows board, firmware and key status at the top; ADB Mode is inside
# "other options". Network ADB on 5555 opens at once, survives reboots (persist.adb.tcp.port), and the usual
# "Allow USB debugging?" prompt follows (ro.adb.secure=1). Touch nothing else there: "Aging mode" starts a
# full-screen colour burn-in pattern that no remote key or menu stops (pulling the mains plug for a minute
# does), and Factory mode, Factory Reset and Shipping Mode sit next to it. Opening the menu did not set Factory
# mode on this set. Users report that newer YaOS updates remove the way in, one more reason the CVTE updater
# is listed below. Switch ADB Mode off in the same menu when you are done.
#
# Keep com.yandex.tv.home ENABLED even with another launcher as Home. The remote's Input, Settings and Alice
# buttons go to the accessibility service com.yandex.tv.services/.keyinterceptor.KeyEventInterceptorService,
# which routes them through com.yandex.tv.home (com.yandex.tv.home.ACTION_ROUTER_INTENT). With it disabled the
# Input and Settings buttons started nothing and Alice answered by voice without showing properly. Enabled but
# not the default, it leaves Home alone (set-home-activity holds, after a reboot too), Input opens Yandex's
# source picker (yandex.intent.action.TV_SOURCE) and Settings the TV settings panel, from any app. The launcher's own InputKeyService and
# HomeKeyService cannot help here: com.yandex.tv.services.platform watches enabled_accessibility_services and
# puts its own list back within milliseconds.
#
# Launcher on YaOS: com.yandex.tv.live requires yandex.tv.permission.ACCESS_TV_SOURCE (normal, the launcher
# declares it). The standard content://android.media.tv/passthrough/<input> URI goes to its channel player,
# which resumes the last Kinopoisk film instead of switching; its source player answers the same URI with the
# live-tv:// scheme, hence "input_uri_scheme": "live-tv" in config.json. HDMI-CEC device inputs (a PS5 on
# HDMI 3) work that way and wake the device. The MediaTek tuner app (com.mediatek.wwtv.tvcenter) has no
# channels on YaOS, so live_tv_package is empty. Remote: SETTINGS is keycode 176, TV_INPUT 178, TV 170.
#
# Apps without Google Play: SmartTube (GitHub yuliskov/SmartTube, armeabi-v7a build; the userland is 32-bit)
# and Apple TV 17.0.0, the Android TV build for API 26 (base + config.armeabi_v7a split; newer builds need
# API 29), both installed over ADB and both play without Google services. TV Bro (GitHub truefedex/tv-bro) in
# its geckoExcluded build runs on the system WebView (113 here); the Gecko build is 150 MB, too big for /data. AdGuard Private DNS breaks Apple TV:
# trailers and the ad-tier pre-roll play, then the film's licence request fails (CdmImplementation rval 7),
# with iadsdk.apple.com, api-adservices.apple.com and Apple's *metrics.apple.com hosts answered as 0.0.0.0.
# With private_dns_mode back on opportunistic the film plays, so the tested set runs without it.
#
# Load-bearing, keep: com.yandex.tv.live (tuner, HDMI and AV player), com.yandex.tv.services and
# com.yandex.tv.services.privileged/.platform (remote keys, power, Wi-Fi, HDMI-CEC), com.yandex.tv.settings,
# com.yandex.server.SystemExtensionService, ru.yandex.androidkeyboard.tv (the only keyboard), every
# com.mediatek.* TV input package, com.mediatek.autopair (remote pairing), and the CVTE factory packages
# (mediatek.factorymenu.ui is the service menu that switches ADB back off). com.yandex.tv.setupwizard stays
# too: the Wi-Fi network saved during first setup belongs to it (dumpsys wifi: cname=com.yandex.tv.setupwizard),
# and it carries the Bluetooth remote pairing screen. Its HOME activity is already disabled after setup.
# Protected, cannot be disabled (SecurityException): com.yandex.launcher.updaterapp (Yandex app and system
# updater).
